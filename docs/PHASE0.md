# 階段 0：工作清單與驗收標準

> 狀態：規劃稿，尚未開發。對應 [PLAN.md](PLAN.md) 第 9 節階段 0，細節依 [TECH_DESIGN.md](TECH_DESIGN.md) 與 [UI_DESIGN.md](UI_DESIGN.md)。
> 目標：交付一個「可登入、有角色、有版型、有說明頁與參考資料頁、有稽核與備份基礎」的空殼系統，為階段 1 的填報功能打好地基。

## 1. 範圍

**做**
1. Laravel 專案骨架、工具鏈、CI、Docker 開發與部署環境
2. SQLite 設定與階段 0 的資料表（見 TECH_DESIGN 第 12 節）
3. 稽核紀錄基礎（只增、雜湊鏈）
4. 登入、帳號管理、角色與授權、首次改密碼、登入節流
5. 淺色版型與共用元件、暫用標誌與 favicon
6. 說明頁框架（Markdown 渲染、目錄、[R-xx] 引用、佔位內容）
7. 參考資料頁（列表、篩選、匯出、後台維護）
8. 後台基礎：使用者、部門、設定
9. 營運基礎：備份指令、健康檢查、日誌、錯誤頁

**不做**（留待後續階段）
- 排放源、係數、活動資料、填報表單、審核（階段 1）
- Dashboard、報表、目標、範疇三（階段 2 起）
- 雙因素驗證、Email 提醒（階段 7；僅預留設定項）
- 說明頁正式文案（由廠務撰寫，階段 0 只放佔位）

## 3. 工作包

規模：S（半天內）、M（約 1 天）、L（約 2 天）。**這是估計，不是承諾**，依實際遇到的問題調整。

### WP0.1 專案初始化與工具鏈（M）

**任務**
1. 核對 Laravel 當時穩定版與相依套件相容性，記錄於 README。
2. 建立專案，設定 zh_TW、時區 Asia/Taipei、資料以 UTC 儲存。
3. 安裝與設定：Pest、Laravel Pint、Larastan、Breeze（Blade）精簡版。
4. 建立 `.env.example`、`config/carbon.php`（捨入規則、上傳限制、預設 GWP 名稱的佔位）。
5. GitHub Actions：Pint、Larastan、Pest（SQLite）、Pest（MySQL 服務容器）、`npm run build`。
6. README：安裝、啟動、測試、目錄說明、貢獻規範。

**驗收標準**
- [ ] 全新複製專案後，照 README 執行安裝指令即可啟動並看到登入頁。
- [ ] CI 全綠：格式、靜態分析、測試（SQLite 與 MySQL 兩套）皆通過。
- [ ] README 載明所採用 Laravel 與主要套件的版本及選擇理由。
- [ ] `.env` 不進版本控制；`.env.example` 不含任何真實密碼或金鑰。

### WP0.2 資料庫與 SQLite 設定（M）

**任務**
1. SQLite 連線：啟用外鍵、WAL、busy_timeout、synchronous；資料庫檔放在網站根目錄之外。
2. 階段 0 遷移：`entities`、`sites`、`departments`、`users`、`sessions`、`cache`、`jobs`、`failed_jobs`、`password_reset_tokens`、`audit_logs`、`settings`、`references`、`page_references`。
3. 列舉值產生 CHECK 約束；所有外鍵設定刪除規則。
4. 種子：部門（5 個）、參考資料 R-01 至 R-14（狀態如實）、預設設定、一個初始管理員（密碼由安裝流程互動設定，不寫死）。
5. 在 CI 中同時於 SQLite 與 MySQL 執行遷移與回滾。

**驗收標準**
- [ ] 啟動後查詢確認 `foreign_keys=1`、`journal_mode=wal`。
- [ ] 遷移可完整執行與回滾，在 SQLite 與 MySQL 8 皆成功。
- [ ] 嘗試寫入不合法的列舉值會被資料庫拒絕（有測試）。
- [ ] 刪除仍被參照的部門會被拒絕。
- [ ] 種子執行兩次不會產生重複資料（可重複執行）。
- [ ] 專案內找不到任何寫死的預設密碼。

### WP0.3 稽核基礎（M）

**任務**
1. `AuditWriter` 服務與模型觀察者：記錄建立、更新、刪除、狀態變更、登入、匯出。
2. `audit_logs` 只增不改：應用層禁止更新與刪除，並加資料庫觸發器作為第二道防線。
3. 雜湊鏈：每筆含前一筆雜湊，並提供驗證指令與排程。
4. 敏感欄位（密碼、記住我權杖）不寫入舊值與新值。

**驗收標準**
- [ ] 建立、修改、停用使用者與修改設定，都會產生對應稽核紀錄，內容含操作者、時間、前後值。
- [ ] 登入成功、失敗、登出皆有紀錄。
- [ ] 嘗試更新或刪除稽核紀錄會失敗（應用層與資料庫層各有測試）。
- [ ] 手動竄改一筆紀錄後，驗證指令能指出被竄改的位置。
- [ ] 稽核紀錄中搜尋不到任何密碼雜湊。

### WP0.4 認證與帳號（M）

**任務**
1. 移除公開註冊；管理員建立帳號並設定臨時密碼。
2. 首次登入強制改密碼；密碼規則（長度、常見弱密碼檢查）。
3. 登入節流：連續錯誤 5 次鎖定 15 分鐘；錯誤訊息不透露帳號是否存在。
4. Session 逾時 2 小時；登出清除 Session。
5. 停用帳號而非刪除；停用者立即無法登入且既有 Session 失效。
6. 忘記密碼：階段 0 先走「聯絡管理員重設」，不開放自助重設信件。

**驗收標準**
- [ ] 沒有任何註冊入口或路由（有測試確認路由不存在）。
- [ ] 以正確帳密登入成功；臨時密碼首次登入會被導向改密碼頁，改完才能使用系統。
- [ ] 同一帳號連續輸入錯誤密碼 5 次後，第 6 次即使密碼正確也被拒絕，並顯示鎖定時間；15 分鐘後可再登入。
- [ ] 輸入不存在的帳號與錯誤密碼，兩者顯示相同訊息、回應時間無明顯差異。
- [ ] 管理員停用某帳號後，該帳號的既有登入立即失效。
- [ ] 弱密碼（過短、常見字串）被拒絕並說明規則。

**任務**

2. 主選單依角色顯示（沒有權限者不顯示）；首頁依角色導向。
3. 403 與 404 頁面：說明原因與可聯絡對象。
4. 職務分離規則的共用檢查（階段 1 使用，階段 0 先建立並測試）。

**驗收標準**
- [ ] 7 種角色各有一個測試帳號，登入後選單與首頁符合 UI_DESIGN 第 3 節表格。
- [ ] 直接輸入沒有權限的網址，得到 403 頁面（不是空白、也不是 500）。
- [ ] 授權矩陣有自動化測試，每個角色對每個後台區域都有「允許」與「拒絕」案例。
- [ ] 稽核唯讀角色在任何頁面都找不到可送出寫入的按鈕，且直接送出寫入請求也被拒絕。

### WP0.6 版型與設計系統（L）

**任務**
1. Tailwind 設定：色票、字型、間距、圓角以 CSS 變數與設計代幣定義，對照 UI_DESIGN 第 2 節。
2. 版型：頂部導覽、麵包屑、頁尾（系統版本與資料截止日）、頁面容器。
3. 共用元件（Blade 元件）：狀態標籤、按鈕、卡片、提示條、表格、表單欄位（含錯誤訊息）、抽屜、空狀態、確認視窗。
4. 標誌與 favicon：採用 `docs/brand/` 的暫用版本。
5. 一個「元件展示頁」（僅 local 環境可見），列出所有元件與狀態，供視覺驗收與回歸比對。
6. 響應式：≥1024、640–1023、<640 三種寬度。

**驗收標準**
- [ ] 元件展示頁涵蓋所有共用元件與每一種狀態（含錯誤、空、載入）。
- [ ] 在 1280、768、390 寬度下，各頁面無橫向捲動（有自動化截圖檢查）。
- [ ] 文字對背景對比度皆 ≥ 4.5:1，元件邊界 ≥ 3:1（以工具逐組驗證並留存結果）。
- [ ] 全站可只用鍵盤操作；焦點樣式僅在鍵盤聚焦時出現且清晰可見。
- [ ] 狀態標籤、完整度等所有狀態表達皆含文字，不只靠顏色。
- [ ] 尊重「減少動態效果」設定。
- [ ] 圖表函式庫與字型由本機提供，頁面載入時沒有任何對外網路請求。

### WP0.7 說明頁框架（M）

**任務**
1. 以 `resources/content/**/*.md` 為內容來源，front matter 含標題、排序、負責人、最後更新日、引用清單。
2. Markdown 渲染（含表格、提示區塊語法），輸出符合版型。
3. 側邊目錄（桌機）與下拉目錄（手機）；麵包屑；上一頁與下一頁。
4. `[R-xx]` 引用解析：連到參考資料頁；若引用的資料狀態為「二手」或「待核對」，頁內自動顯示警示條。
5. 佔位內容骨架：總覽、範疇一（固定燃燒、移動燃燒、逸散）、範疇二、範疇三、方法學、填報 SOP、常見問題、名詞表，每頁含固定結構（一句話重點、你需要準備什麼、怎麼算、前往填報）與「內容待廠務確認」標示。
6. 內容檔安全：渲染時清除不安全的 HTML。

**驗收標準**
- [ ] 所有骨架頁面皆可開啟，結構一致，且都標示「內容待廠務確認」。
- [ ] 在 Markdown 中寫 `[R-13]`，頁面會產生連到參考資料頁的連結；因 R-13 為待核對，頁內自動出現警示條。
- [ ] 引用不存在的編號時，建置或測試階段即報錯（不是上線後才發現）。
- [ ] 在內容中嵌入惡意腳本不會被執行（有測試）。
- [ ] 手機寬度下目錄改為下拉且可操作。
- [ ] 新增一個說明頁只需新增一個 Markdown 檔，不需改程式。

### WP0.8 參考資料頁（M）

**任務**
1. 列表頁：欄位、篩選（核對狀態、關鍵字）、核對超過 12 個月顯示「需複核」。
2. 展開檢視：連結、用途、核對人、備註、哪些頁面引用。
3. 後台維護：新增、編輯、核對狀態更新（需填核對日與核對人）；所有異動寫稽核。
4. 匯出參考資料清單（CSV 與 PDF 或 Excel 其一，階段 0 先做 CSV）。
5. 種子資料：R-01 至 R-14，狀態與 PLAN.md 第 11 節一致。

**驗收標準**
- [ ] 列表正確顯示 14 筆，依狀態篩選結果正確。
- [ ] 把某筆狀態改為「原文」時，必須填核對日與核對人，否則無法儲存。
- [ ] 非管理員看不到編輯入口，直接送出編輯請求被拒。
- [ ] 每次修改都有稽核紀錄。
- [ ] 匯出的 CSV 在 Excel 開啟時中文不亂碼（含 BOM）。
- [ ] 把核對日改成 13 個月前，該筆顯示「需複核」。

### WP0.9 後台基礎（M）

**任務**
1. 使用者管理：列表、新增、編輯、停用、重設臨時密碼。
2. 部門管理：列表、新增、編輯、停用（被使用者參照者不可刪）。
3. 設定管理：集中於一個頁面，分組顯示（填報時程、異常門檻、提醒天數、捨入規則）；階段 0 先放填報時程的預設值（UI_DESIGN 5.1）。
4. 稽核紀錄檢視頁：篩選（操作者、事件、日期）、顯示前後值差異，只讀。

**驗收標準**
- [ ] 管理員可完成使用者與部門的新增、修改、停用，並都留有稽核紀錄。
- [ ] 修改填報時程設定後，設定頁與資料庫的值一致，且有稽核紀錄。
- [ ] 設定值格式錯誤（如日期為負、百分比超過 100）被拒絕並說明。
- [ ] 稽核紀錄頁可依操作者與日期篩選，且完全唯讀。

### WP0.10 營運基礎（M）

**任務**
1. Docker Compose：php-fpm、nginx、掛載資料與儲存目錄；可選的 MySQL profile。
2. 備份指令：以 `VACUUM INTO` 產生一致性資料庫副本，連同私有儲存目錄打包，保留 30 份；附還原指令與說明。
3. 健康檢查端點（不含敏感資訊）、結構化日誌、錯誤頁（500 不洩漏技術細節）。
4. 排程：備份、稽核鏈驗證；在文件中說明如何在主機上設定 cron。
5. 安全標頭與內容安全政策；強制 HTTPS（生產環境）。

**驗收標準**
- [ ] 以 Docker Compose 一個指令可啟動完整系統；SQLite 檔案與上傳目錄存放於掛載的資料卷，重建容器後資料仍在。
- [ ] 備份指令產生的副本可被獨立開啟並查詢到資料；**執行過一次完整還原演練**（刪掉資料後由備份還原，系統可正常使用），並把步驟寫入文件。
- [ ] 備份只保留最新 30 份。
- [ ] 健康檢查端點在資料庫正常時回應成功，資料庫不可用時回應失敗。
- [ ] 觸發一個內部錯誤時，使用者只看到通用錯誤頁，日誌有詳細資訊。
- [ ] 回應標頭含基本安全標頭；階段 0 頁面在內容安全政策下無違規。

3. 更新 README、TECH_DESIGN 與 PLAN 中因實作而產生的差異。
4. 準備驗收展示腳本與展示資料。

**驗收標準**
- [ ] 無障礙工具對所有階段 0 頁面無嚴重與重大問題；人工鍵盤與螢幕閱讀器抽查通過。
- [ ] 安全檢查清單逐項完成並留存結果。
- [ ] 文件與實作一致，差異已更新。

## 4. 驗收展示腳本（使用者驗收時照此走一遍）

1. 以管理員登入 → 被要求改臨時密碼 → 改完進入後台。
2. 建立 7 個角色各一個帳號；以其中兩個角色登入，確認選單與首頁不同。
3. 以填報者嘗試直接輸入後台網址，看到 403 頁面。
4. 連續輸入錯誤密碼 5 次，看到鎖定訊息。
5. 開啟說明頁：瀏覽目錄、看到「內容待廠務確認」標示；開啟含 [R-13] 的頁面，看到引用連結與警示條。
6. 開啟參考資料頁：篩選「待核對」、把某筆改為「原文」（填核對日與核對人）、匯出 CSV 用 Excel 開啟。
7. 到稽核紀錄頁，找到剛才所有操作的紀錄；說明竄改驗證指令如何運作。
8. 手機寬度開啟說明頁與參考資料頁。
9. 展示備份與還原。

## 7. 提交策略

- 以工作包為單位提交，訊息說明做了什麼與為什麼；每個工作包完成並通過 CI 後推送。
