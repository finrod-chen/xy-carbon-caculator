# 喜躍生醫 內部碳盤查網站：介面設計規格

> 狀態：設計稿，尚未開發。對應 [PLAN.md](PLAN.md) 第 6 版與 [TECH_DESIGN.md](TECH_DESIGN.md)。
> 視覺線稿：[wireframes/index.html](wireframes/index.html)（用瀏覽器直接開啟，點上方頁籤切換 10 個畫面；所有數字皆為示意）。

## 1. 設計方向

簡約實用、淺色。原則：

1. **先講資料可不可信，再講數字**：Dashboard 與報表都先顯示完整度與核對狀態。
2. **一個畫面完成一件事**：填報者看「我要交什麼」，審核者看「這筆能不能過」，主管看「要不要我處理」。
3. **狀態一律顏色加文字**：不只靠顏色區分，色弱與黑白列印都看得懂。
4. **不確定的就明說**：待核對的係數、草稿目標、二手出處，都在畫面上直接標示，不隱藏。
5. **少即是多**：單一綠色主色；不使用裝飾性漸層、陰影與動畫（只保留必要的狀態轉換）。

## 2. 設計語彙

### 2.1 色彩（淺色主題）

| 用途 | 色票 | 說明 |
|---|---|---|
| 背景 | `#FFFFFF`、區塊底 `#F6F8F6` | 白底為主 |
| 文字 | 主 `#1D2A22`、次 `#5B6A61` | 次要文字對白底對比約 5:1 以上 |
| 邊框 | `#DFE5E0` | 一般分隔線 |
| 主色（綠） | `#2C7A4B`，淡底 `#E6F2EA` | 主要按鈕、目前選單、已核准 |
| 提示（琥珀） | `#9A6A10`，淡底 `#FBF1DA` | 草稿、警示、待核對 |
| 錯誤（紅） | `#B03A3A`，淡底 `#F9E4E4` | 退回、缺資料、逾期 |
| 資訊（藍） | `#31607F`，淡底 `#E4EEF6` | 已送審、說明提示 |

實作時以 CSS 變數定義，並在動工時以對比度工具逐組驗證（文字對背景至少 4.5:1，元件邊界至少 3:1）。第一版只做淺色主題。

### 2.2 字型與間距

- 字型堆疊：Noto Sans TC → PingFang TC → Microsoft JhengHei → 系統預設。內網環境不依賴外部字型服務。
- 內文 15px，表格 13px，標題 18–20px，大數字 26px。僅用一般與半粗兩種字重。
- 間距以 4px 為單位，卡片圓角 8px，欄位圓角 6px。

### 2.3 共用元件

| 元件 | 規則 |
|---|---|
| 狀態標籤（chip） | 一律含文字；顏色對應見下表 |
| 按鈕 | 主按鈕（綠底）每個區塊最多一個；破壞性動作用紅字框線，不用紅底 |
| 表格 | 表頭灰底；窄螢幕可橫向捲動；數值靠右對齊，單位寫在欄名或緊接數值 |
| 卡片 | 白底細邊框，標題 14px 半粗 |
| 抽屜 | 在桌機從右側展開、手機改為整頁；關閉時若有未存內容需確認 |
| 提示條（banner） | 資訊、警示、錯誤三種，皆含文字說明原因與下一步 |
| 完整度矩陣 | 每格有圖例文字；可用鍵盤聚焦，聚焦時顯示該格資訊 |
| 空狀態 | 說明「為什麼是空的」與「下一步做什麼」，附一個主要動作 |

狀態標籤對照：

| 對象 | 狀態與顏色 |
|---|---|
| 活動資料 | 草稿（琥珀）、已送審（藍）、已退回（紅）、已核准（綠）、已鎖定（深綠） |
| 出處核對 | 原文（綠）、二手（琥珀）、待核對（紅） |
| 係數 | 草稿（琥珀）、已核對（藍）、啟用（綠）、停用（灰） |
| 目標 | 草稿（琥珀）、已核准、已註冊、已提交、已驗證 |
| 異常 | 提示（藍）、警示（琥珀）、高風險（紅） |

## 3. 資訊架構與導覽

主選單（登入後固定在頂部）：**說明 · 填報 · 審核 · Dashboard · 目標與措施 · 報表 · 後台**。依角色顯示，沒有權限的項目不出現（不是灰掉）。

| 角色 | 預設首頁 | 可見選單 |
|---|---|---|
| 填報者 | 填報首頁 | 說明、填報 |
| 單位主管 | 部門視圖 Dashboard | 說明、填報、審核（本部門）、Dashboard |
| 審核者 | 審核佇列 | 說明、審核、Dashboard、報表 |
| 管理者 | Dashboard | 說明、審核、Dashboard、目標與措施、報表 |
| ESG 窗口 | 目標與措施 | 說明、Dashboard、目標與措施、報表 |
| 系統管理員 | 後台 | 全部 |
| 稽核唯讀 | Dashboard | 全部（唯讀） |

全站固定元素：頁首使用者選單（個人設定、登出）、麵包屑、頁尾顯示系統版本與資料截止日。

## 4. 畫面規格

以下對應線稿頁籤。每個畫面列出用途、主要內容、關鍵規則與狀態。

### 4.1 登入
- 欄位：公司信箱、密碼。
- 規則：錯誤訊息不透露帳號是否存在；連續錯誤 5 次鎖定 15 分鐘；首次登入強制改密碼。
- 狀態：一般、錯誤、鎖定、需改密碼。

### 4.2 填報首頁
- 內容：本月進度條與截止日倒數、被退回與缺佐證的數量、「本月應提供資料」清單。
- 清單來源：排放源目錄 × 使用者部門 × 填報頻率，不顯示其他部門。
- 「本月無此項」：獨立動作，需寫原因，系統記為 0 並留痕，與「尚未填」區分。
- 排序：已退回置頂，其次草稿，其次尚未填。
- 空狀態：本月全部完成時顯示完成訊息與下月提醒日。

### 4.3 月份填報
- 版面：左表格、右抽屜（桌機）；手機為整頁編輯。
- 表格欄位：排放源、數量與單位、佐證、狀態、提示。
- 抽屜欄位：排放源、處理方式／係數、數量、單位、資料性質、是否估算與估算方法、佐證檔、備註。
- 即時預覽：顯示換算排放量、係數單位、GWP 版本；標明這是預覽，送審時才凍結。
- 驗證與提示：
  - 單位只列該排放源允許的單位；
  - 要求佐證的排放源，送審前必須有檔案；
  - 勾選「估算」才出現必填的「估算方法」；
  - 與上月、去年同月的偏差超過門檻時，顯示百分比並要求備註；
  - 使用待核對的係數時，預覽處顯示警示。
- 動作：儲存草稿、全部送審（送審前列出將被送審的項目與未通過的檢查）。
- 鎖定狀態：整頁唯讀，頁頂顯示鎖定人與日期，並提供「申請解鎖」。

### 4.4 審核
- 版面：左側佇列、右側單筆詳情。
- 佇列篩選：狀態、風險、部門、月份；排序預設為高風險優先。
- 詳情：填報者與送審時間、數量與資料性質、凍結的係數與出處與核對狀態、GWP 版本、排放量（可展開分氣體）、與上月和去年同月比較、佐證預覽、異常清單。
- 動作：核准、退回（必填意見）。不得核准自己填的資料。
- 鍵盤：上下鍵切換、快速鍵核准與退回；所有動作寫入審核歷程。
- 批次：月底可「整月批次核准」，僅限無異常項目；有異常者須逐筆處理。

### 4.5 主管 Dashboard
- 版面由上到下：年度與完整度 → 四張 KPI（累計排放、範疇占比、估算占比、待處理）→ 完整度矩陣 → 月趨勢、排放熱點、異常與待辦 → 減碳目標進度。
- 口徑：KPI 只計已核准與已鎖定；草稿與送審另列「待確認」。
- 完整度矩陣：列為排放源、欄為月份；每格狀態取該格所有紀錄中最低的狀態；缺資料格可看負責部門與負責人，並提供催辦。
- 異常與待辦：可直接跳到審核頁或催辦。
- 目標卡：目標未核准時顯示「草稿」；顯示實際、路徑、差距與措施預估可補足量。
- 篩選：年度、部門視圖（單位主管預設自己部門）。
- 空狀態：年度尚無資料時，顯示「尚未開始填報」與前往填報的入口。

### 4.6 目標與措施
- 頂部提示：公司類別未判定時顯示橫幅並阻擋產出 SBTi 資料包。
- 目標摘要：範圍、盤查基準年、目標基準年、目標期間、減量幅度、核准狀態；減量幅度不預填未驗證數字。
- SBTi 檢核：逐項顯示通過／未通過／待處理，每項可展開看條號與出處；項目與門檻來自 SBTi 參數表。
- 措施表：名稱、部門、影響排放源、狀態、預估年減量、驗證實際；年度結束時提醒填實際值。
- 附屬分頁：碳權（獨立記錄，不計入減量）、情境試算器、基準年重算紀錄、目標版本歷史。

### 4.7 說明頁
- 版面：左側目錄、右側文章；手機改為頁頂下拉目錄。
- 固定結構：一句話重點 → 你需要準備什麼 → 怎麼算 → 前往填報。
- 引用：以 [R-xx] 標註，連到參考資料頁；引用到「待核對」或「二手」資料時，頁內顯示警示條。
- 頁尾：最後更新日、負責人。內容以 Markdown 檔維護。

### 4.8 參考資料頁
- 列表欄位：編號、資料、發布單位與版本、用途、核對狀態、最後核對日。
- 篩選：狀態、關鍵字；可匯出清單。
- 展開：連結、用途對應的站內位置（係數、參數、頁面）、核對人、備註。
- 核對超過 12 個月顯示「需複核」。

### 4.9 係數庫與核對（後台）
- 列表：排放源、係數名稱、每單位排放量、適用年度、出處與其核對狀態、狀態。
- 核對抽屜：並排「系統值」與「原始公告值」，須附公告連結或附件；不一致時阻擋；出處為二手時不得設為已核對。
- 啟用後再改值會產生新版本，舊版保留，歷史資料不受影響。

### 4.10 報表中心
- 四類報表卡：ISO 14064-1 盤查報告、永續報告氣候章節、SBTi 提交資料包、查證包；各自顯示最新版本與狀態。
- 產生前檢查（公開顯示）：期間是否全數鎖定、有無未解決異常、引用的係數是否皆已核對、公司類別是否已判定（僅 SBTi 包）。未通過則顯示原因與前往處理的連結。
- 版本歷史：版本號、狀態、產生者、快照雜湊、核准人；已發布版本不可覆蓋。
- 報告首頁固定印出資料截止日、版本、係數與 GWP 版本、核對狀態摘要。

## 5. 通用狀態與文案

| 情境 | 規則 |
|---|---|
| 載入中 | 區塊骨架佔位，不用整頁轉圈 |
| 空狀態 | 說明原因加一個主要動作 |
| 錯誤 | 說明發生什麼事、使用者可以怎麼做；不顯示技術訊息 |
| 儲存成功 | 輕提示條，3 秒後消失，不攔截操作 |
| 危險動作 | 解鎖、退回、核准、發布皆需確認，確認視窗寫明影響 |
| 權限不足 | 顯示「你沒有此頁權限」與可聯絡的人，不顯示空白或 404 |

文案原則：正體中文、用詞固定（「活動數據」「排放係數」「核准」「鎖定」不混用同義詞）、日期格式 `2026-11-08`、數字加千分位、單位緊接數值並附空格（`12,480 kWh`）、排放量預設 tCO₂e、明細可切換 kgCO₂e。

## 6. 響應式

| 寬度 | 規則 |
|---|---|
| ≥ 1024 | 多欄卡片；填報頁左表右抽屜；說明頁側邊目錄 |
| 640–1023 | 卡片兩欄；抽屜覆蓋右側 |
| < 640 | 單欄；抽屜改整頁；矩陣橫向捲動；表格可橫向捲動；說明目錄改下拉 |

填報頁與審核頁以桌機為主要使用情境，手機需可查看與補件，但完整度矩陣與報表不要求手機最佳化。

## 7. 無障礙

- 語意化標題階層與地標區域；表單欄位皆有明確標籤；錯誤訊息與欄位以 aria 關聯。
- 全站可用鍵盤操作；焦點樣式清晰，僅在鍵盤聚焦時顯示。
- 狀態不只靠顏色；圖表另附資料表或文字摘要。
- 點擊目標至少 32px 高，行動版 44px。
- 尊重使用者「減少動態效果」設定。
- 動工後以自動化工具加人工檢查，目標為 WCAG 2.1 AA。

## 8. 待確認

1. 公司商標與正式品牌色：目前使用中性綠色，若有品牌規範，替換主色並重新驗證對比。
2. 說明頁文案由誰撰寫與審稿（生技設備清單、廠內流程需要在地內容）。
3. 是否需要英文介面（規劃書目前定為正體中文）。
4. 審核頁鍵盤快速鍵偏好。
5. 填報截止日與提醒信的預設天數。
