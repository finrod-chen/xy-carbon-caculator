# 喜躍生醫 內部碳盤查網站：規劃書（第 4 版：新增減碳目標與永續報告書）

> 狀態：規劃完成，尚未開發。本文件記錄已確認的決策、範圍、架構與開發階段。
> 排放係數與法規相關內容為規劃時的整理，上線前須對照環境部、能源署最新公告核對。

## 1. 專案目標

為喜躍生醫建立內部使用的溫室氣體（碳）盤查系統，達成：

1. 提供各範疇的說明頁面，讓填報者看得懂要填什麼、為什麼要填。
2. 提供實際收集活動數據的表單，並自動換算排放量。
3. 提供審核流程與稽核軌跡，資料可供日後外部查證。
4. 提供主管「快掃確認」的 Dashboard。
5. 輸出符合 ISO 14064-1:2018 結構的報表。
6. 設定減碳目標，追蹤實際排放與目標路徑的差距，並管理減碳措施。
7. 輔助產出永續報告書的環境與氣候章節（GRI、TCFD／IFRS S2 對照），確保對外數字與盤查數字一致。

## 3. 參考的市面產品與標準

- Watershed、Persefoni：依範疇與類別拆分收集、排放熱點、審核與稽核軌跡。
- Microsoft Sustainability Manager：活動數據 × 排放係數的資料模型、係數庫版本管理。
- Plan A、Normative、Greenly：簡潔的填報引導、支出法與活動數據法並用。
- 台灣在地資料來源：環境部溫室氣體排放係數管理表、能源署公告之電力排碳係數。
- 標準：ISO 14064-1:2018（類別 1 至 6）、GHG Protocol Corporate Standard 與 Scope 3 Standard。

## 4. 功能範圍

### 4.1 說明頁面（唯讀）

- 碳盤查總覽：目的、組織邊界、基準年、流程圖
- 範疇一（ISO 類別 1）：固定燃燒、移動燃燒、逸散（冷媒、滅火器、化糞池）、製程
- 範疇二（ISO 類別 2）：外購電力（位置基準，保留市場基準）
- 範疇三（ISO 類別 3 至 6）：15 類說明、生技業常見項目、納入與排除理由
- 方法學：排放量計算公式、GWP 版本、係數來源、數據品質分級、不確定性
- 填報 SOP、FAQ、名詞表

### 4.2 填報表單

- 依「排放源 × 月份」填報：數量、單位、佐證檔案、備註
- 即時換算 tCO₂e，單位不符或數值異常時提示
- 「本月應提供資料」引導清單，降低遺漏
- 估算標記：缺漏月份可標「估算」，必填估算方法，納入數據品質評分
- 歷史回補：允許選擇過去月份填報（2025 年全年）
- 狀態流轉：草稿 → 送審 → 退回／核准；核准後鎖定該期間，修改須申請解鎖並記錄理由
- 批次匯入：CSV／Excel 範本（如電費帳單）

### 4.3 範疇三（兩階段）

1. **重大性篩選**：15 類逐一評估，記錄納入或排除理由與評估準則（ISO 14064-1 要求的重大性判斷）。
2. **資料收集**：納入類別先以採購支出 × 支出係數估算，重要類別再升級為活動數據法（如運輸重量 × 距離）。
   - 首批候選：外購商品與服務、運輸、廢棄物、員工通勤、出差。
   - 支出係數可能需採用國外 EEIO 係數，方法學頁與報告須標示為粗估。

### 4.4 主管快掃 Dashboard

- KPI：本年累計 tCO₂e、與基準年／去年同期比較、各範疇占比
- 完整度矩陣：排放類別（行）× 月份（列）的紅黃綠燈
- 異常清單：與上月偏差過大、0 值、單位可疑
- 數據品質：估算占比、佐證缺漏
- 待審核佇列：一鍵核准或退回
- 排放熱點（前幾名來源）與月趨勢圖
- 強度指標：每員工、每坪、每營收
- 減碳目標進度卡：實際排放 vs 目標路徑、差距、紅黃綠狀態、已核准措施可抵減的量

### 4.5 報表輸出

- 年度盤查清冊（Excel）
- 盤查報告書草稿（PDF，章節對應 ISO 14064-1）
- 稽核用明細（每筆含係數、版本、佐證連結）
- 主管摘要頁（單頁 PDF）

### 4.6 後台

- 使用者、部門與角色
- 排放源目錄、排放係數庫（版本化）、GWP 版本
- 組織設定、邊界與基準年（設定後鎖定）
- 重大性評估設定
- 係數核對清單頁（逐筆確認來源與年份）

### 4.7 減碳目標與措施

**目標設定**
- 目標類型：絕對量目標與強度目標（每員工、每營收）可並存。公司成長期，只設絕對量容易與業務衝突，因此建議兩種都記錄。
- 欄位：涵蓋範疇（先範疇一加二，範疇三另設）、基準年（2025）、目標年、減量比例、設定依據、核准人與核准日期。
- 路徑：依基準年與目標年自動算出逐年目標路徑（預設線性），並可手動調整年度里程碑。
- 參考基準（開發時須核對最新版本）：科學基礎減量目標倡議（SBTi）的 1.5°C 對齊路徑，以及國家淨零與減量目標。系統提供對照說明，但目標數值由公司管理層決定。
- 目標異動留痕：任何修改須填理由，並保留歷史版本。

**進度追蹤**
- 每月／每年自動比對實際排放與目標路徑，計算差距與達成率。
- 範疇三另設追蹤，因為測量不確定性高，目標以「供應商參與」「資料品質提升」等過程指標為輔。

**基準年重新計算**
- 設定重新計算政策與重大性門檻（如組織變動、方法或係數變更、發現重大錯誤）。
- 觸發時記錄原因、影響量與前後數字，避免目標進度被非實質變動扭曲。

**減碳措施管理**
- 欄位：措施名稱、負責部門、影響的排放源、預估年減量（tCO₂e）、成本、起訖日期、狀態（構想／規劃／執行中／完成）、驗證後實際減量。
- 預估與實際並列，Dashboard 顯示「措施合計預估減量」與「目標差距」，看出措施夠不夠。
- 情境試算器：如汰換冷媒、改用電動車、冷鏈優化、節能改善，輸入參數即得預估減量，輔助決策。
- 抵換（碳權）不計入減量進度，另欄位獨立記錄，避免對外宣稱失真。

### 4.8 永續報告書輔助

**定位**：永續報告書涵蓋環境、社會、公司治理，範圍遠大於碳盤查。本系統只負責「環境與氣候章節」所需的資料與表格，其他章節以文字範本與披露對照清單輔助，不做完整 ESG 平台。若日後要擴充社會與治理資料，另案評估。

**環境績效指標（補充收集）**
- 能源：由電力與燃料活動數據換算 GJ（需在排放源目錄加能源換算係數）
- 用水量、廢棄物量與處理方式：用水為新增填報項目，廢棄物沿用範疇三資料
- 員工人數：沿用人資填報，作為強度分母

**披露對照（GRI Standards）**
- GRI 305：排放（305-1 直接、305-2 能源間接、305-3 其他間接、305-4 強度、305-5 減量）
- GRI 302：能源（302-1 能源消耗、302-3 能源密集度、302-4 節能成果）
- GRI 303、306：用水與廢棄物（視資料可得性）
- 提供「GRI 索引表」：每個披露項目對應系統中的資料來源與頁碼，缺資料處標示紅燈

**氣候相關揭露（TCFD／IFRS S2）**
- 四大支柱範本：治理、策略、風險管理、指標與目標
- 氣候風險與機會登錄表：類型（實體風險／轉型風險／機會）、描述、時間範圍、定性財務影響、因應措施、負責部門
- 指標與目標章節由 4.7 的目標與盤查數據自動帶入

**報告產出**
- 環境章節 Word（.docx）：範本文字 + 自動帶入的數字與表格，使用者可再編輯，因永續報告書通常需排版或匯入設計軟體
- 數據附表 Excel：供編輯與查證
- **發布版本快照**：報告引用的數字來自已鎖定期間的凍結快照，並記錄版本與核准人。盤查報告書與永續報告書的數字因此必然一致，修改後須產生新版本，不能悄悄覆蓋。
- 查證包：附佐證檔與稽核軌跡的壓縮檔，供第三方查證

## 5. 角色與部門分派

| 部門 | 負責資料 |
|---|---|
| 行政／總務 | 電、水、公務車、冷媒、廢棄物 |
| 採購／財務 | 採購支出（範疇三支出法主要來源） |
| 研發／實驗室 | 實驗氣體、乾冰、動物房麻醉氣體 |
| 人資 | 員工人數、通勤、出差 |
| 管理者 | 審核與主管 Dashboard、核准減碳目標與報告發布 |
| 永續／ESG 窗口（人選待定） | 減碳措施與氣候風險登錄、永續報告書編輯 |

系統角色：填報者、單位主管、審核者、管理員、稽核唯讀。部門分派可在後台調整。

## 6. 技術架構

- 後端：Laravel（登入、權限、CSRF、遷移、驗證皆用框架內建）
- 資料庫：SQLite（WAL），遷移檔管理結構；避免 SQLite 專屬語法
- 前端：Blade + 少量 Alpine.js；圖表使用 Chart.js，並本地化放置（內網，不依賴 CDN）
- 報表：Excel 用 PhpSpreadsheet；PDF 用 Dompdf 或 mPDF，內嵌 Noto Sans TC
- 檔案：佐證檔存私有目錄，不放公開路徑，上傳須驗證類型與大小
- 部署：Docker Compose 提供執行環境，方便搬入內網
- 風格：白底、灰階 + 單一綠色主色、大量留白、表格清晰

## 7. 核心資料模型

主要資料表：`users`、`departments`、`emission_sources`、`emission_factors`（版本化）、`gwp_sets`、`activity_records`、`attachments`、`reporting_periods`、`materiality_assessments`、`audit_logs`、`settings`。

減碳目標與報告新增：`targets`（含版本歷史）、`target_milestones`、`reduction_initiatives`、`initiative_results`、`recalculation_log`、`performance_indicators`（能源、用水、廢棄物等非排放指標）、`climate_risks`、`disclosure_items`（GRI／TCFD 披露項目與資料來源對照）、`report_versions`（發布版本快照）。

關鍵設計：**每筆填報資料在存檔時凍結當下使用的係數、GWP 版本與計算結果**，之後係數更新不會改動已核准的歷史數字，查證時可完整重現。

## 8. 風險與盲點清單

**盤查方法**
1. 組織邊界與基準年須先定，後續比較皆依賴。
2. 範疇二：GHG Protocol 建議雙報；目前無綠電，僅位置基準，保留市場基準欄位。
3. 排除與重大性門檻須記錄理由，查證時會被問。
4. 每筆資料標示數據品質（實測／帳單／估算）；無歷史資料故估算占比可能偏高。
5. 範疇三 15 類先篩選再收集，避免負擔過重。

**生技業特有排放源（容易漏）**
6. 冷媒：超低溫冰箱、冰水主機、空調逸散，GWP 高。
7. 乾冰與液態二氧化碳（冷鏈、培養箱、實驗）。
8. 動物房麻醉氣體。
9. 冷鏈物流與檢體運送。
10. 實驗廢棄物與拋棄式耗材。
11. 公務車、員工通勤、出差。

**系統與營運**
12. 佐證與稽核軌跡：誰在何時改了什麼都要留痕。
13. 期間鎖定與解鎖申請流程。
14. PDF 中文字型須內嵌。
15. 內網離線：函式庫與字型本地放置。
16. 截止日前 Email 提醒未填報者。
17. 資安：PDO／Eloquent 參數化、密碼雜湊、CSRF、上傳驗證、HTTPS、備份。
18. 指定係數維護者，每年更新並覆核環境部與能源署公告。
19. 預載係數非保證最新，上線前須由公司逐筆核對（提供核對清單頁）。
20. 支出係數在台灣公開資料有限，須在方法學與報告中說明粗估性質。
21. 法規定位：《氣候變遷因應法》主要管制排放大戶，喜躍生醫多屬自願盤查；請依現行法規再核對。
22. 建議各部門在開發期間先整理 2025 年帳單與紀錄，上線即可回補。

**SQLite 注意事項**
23. 開啟 WAL；每日備份資料庫檔與上傳目錄；50 人規模寫入量足夠。

**減碳目標**
24. 基準年 2025 為首次盤查，估算比例可能偏高。建議目標在第一輪盤查通過內部審核後再正式核准，避免基準不穩而反覆調整。
25. 目標數值是管理層決策，系統只記錄、計算與追蹤，不代為決定。
26. 公司成長期的絕對量目標壓力大，須同時看強度目標並說明差異。
27. 基準年重新計算政策要在設定目標前就定好，否則日後無法解釋數字變動。
28. 碳權抵換與實際減量必須分開記錄與呈現，避免對外揭露失真。
29. 範疇三不確定性高，目標宜以過程指標輔助，不宜只看總量。

**永續報告書**
30. 是否有法定或客戶要求編製永續報告書，會決定採用 GRI 或 IFRS S1／S2 為主，目前尚未確認（見待確認事項）。
31. 永續報告書範圍遠大於本系統，須明確劃定只做環境與氣候章節，避免範圍膨脹。
32. 盤查報告與永續報告的數字須來自同一份凍結快照，否則外部查證時會被指出不一致。
33. 對外用語須謹慎：查證狀態、減量成果、「碳中和」之類的宣稱都要有依據。法規與用語規範以現行公告為準。
34. 能源、用水、廢棄物是 GRI 常見揭露項目，若現在不收集，之後回補會很吃力，建議填報表單一併納入。
