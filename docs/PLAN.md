# 喜躍生醫 內部碳盤查網站：規劃書（第 3 版，已定案）

> 狀態：規劃完成，尚未開發。本文件記錄已確認的決策、範圍、架構與開發階段。
> 排放係數與法規相關內容為規劃時的整理，上線前須對照環境部、能源署最新公告核對。

## 1. 專案目標

為喜躍生醫建立內部使用的溫室氣體（碳）盤查系統，達成：

1. 提供各範疇的說明頁面，讓填報者看得懂要填什麼、為什麼要填。
2. 提供實際收集活動數據的表單，並自動換算排放量。
3. 提供審核流程與稽核軌跡，資料可供日後外部查證。
4. 提供主管「快掃確認」的 Dashboard。
5. 輸出符合 ISO 14064-1:2018 結構的報表。

## 3. 參考的市面產品與標準

- Watershed、Persefoni：依範疇與類別拆分收集、排放熱點、審核與稽核軌跡。
- Microsoft Sustainability Manager：活動數據 × 排放係數的資料模型、係數庫版本管理。
- Plan A、Normative、Greenly：簡潔的填報引導、支出法與活動數據法並用。
- 台灣在地資料來源：環境部溫室氣體排放係數管理表、能源署公告之電力排碳係數。
- 標準：ISO 14064-1:2018（類別 1 至 6）、GHG Protocol Corporate Standard 與 Scope 3 Standard。

## 4. 功能範圍

### 4.1 說明頁面（唯讀）

- 碳盤查總覽：目的、組織邊界、基準年、流程圖
- 範疇一（ISO 類別 1）：固定燃燒、移動燃燒、逸散（冷媒、滅火器、化糞池）、製程
- 範疇二（ISO 類別 2）：外購電力（位置基準，保留市場基準）
- 範疇三（ISO 類別 3 至 6）：15 類說明、生技業常見項目、納入與排除理由
- 方法學：排放量計算公式、GWP 版本、係數來源、數據品質分級、不確定性
- 填報 SOP、FAQ、名詞表

### 4.2 填報表單

- 依「排放源 × 月份」填報：數量、單位、佐證檔案、備註
- 即時換算 tCO₂e，單位不符或數值異常時提示
- 「本月應提供資料」引導清單，降低遺漏
- 估算標記：缺漏月份可標「估算」，必填估算方法，納入數據品質評分
- 歷史回補：允許選擇過去月份填報（2025 年全年）
- 狀態流轉：草稿 → 送審 → 退回／核准；核准後鎖定該期間，修改須申請解鎖並記錄理由
- 批次匯入：CSV／Excel 範本（如電費帳單）

### 4.3 範疇三（兩階段）

1. **重大性篩選**：15 類逐一評估，記錄納入或排除理由與評估準則（ISO 14064-1 要求的重大性判斷）。
2. **資料收集**：納入類別先以採購支出 × 支出係數估算，重要類別再升級為活動數據法（如運輸重量 × 距離）。
   - 首批候選：外購商品與服務、運輸、廢棄物、員工通勤、出差。
   - 支出係數可能需採用國外 EEIO 係數，方法學頁與報告須標示為粗估。

### 4.4 主管快掃 Dashboard

- KPI：本年累計 tCO₂e、與基準年／去年同期比較、各範疇占比
- 完整度矩陣：排放類別（行）× 月份（列）的紅黃綠燈
- 異常清單：與上月偏差過大、0 值、單位可疑
- 數據品質：估算占比、佐證缺漏
- 待審核佇列：一鍵核准或退回
- 排放熱點（前幾名來源）與月趨勢圖
- 強度指標：每員工、每坪、每營收

### 4.5 報表輸出

- 年度盤查清冊（Excel）
- 盤查報告書草稿（PDF，章節對應 ISO 14064-1）
- 稽核用明細（每筆含係數、版本、佐證連結）
- 主管摘要頁（單頁 PDF）

### 4.6 後台

- 使用者、部門與角色
- 排放源目錄、排放係數庫（版本化）、GWP 版本
- 組織設定、邊界與基準年（設定後鎖定）
- 重大性評估設定
- 係數核對清單頁（逐筆確認來源與年份）

## 5. 角色與部門分派

| 部門 | 負責資料 |
|---|---|
| 行政／總務 | 電、水、公務車、冷媒、廢棄物 |
| 採購／財務 | 採購支出（範疇三支出法主要來源） |
| 研發／實驗室 | 實驗氣體、乾冰、動物房麻醉氣體 |
| 人資 | 員工人數、通勤、出差 |
| 管理者 | 審核與主管 Dashboard |

系統角色：填報者、單位主管、審核者、管理員、稽核唯讀。部門分派可在後台調整。

## 6. 技術架構

- 後端：Laravel（登入、權限、CSRF、遷移、驗證皆用框架內建）
- 資料庫：SQLite（WAL），遷移檔管理結構；避免 SQLite 專屬語法
- 前端：Blade + 少量 Alpine.js；圖表使用 Chart.js，並本地化放置（內網，不依賴 CDN）
- 報表：Excel 用 PhpSpreadsheet；PDF 用 Dompdf 或 mPDF，內嵌 Noto Sans TC
- 檔案：佐證檔存私有目錄，不放公開路徑，上傳須驗證類型與大小
- 部署：Docker Compose 提供執行環境，方便搬入內網
- 風格：白底、灰階 + 單一綠色主色、大量留白、表格清晰

## 7. 核心資料模型

主要資料表：`users`、`departments`、`emission_sources`、`emission_factors`（版本化）、`gwp_sets`、`activity_records`、`attachments`、`reporting_periods`、`materiality_assessments`、`audit_logs`、`settings`。

關鍵設計：**每筆填報資料在存檔時凍結當下使用的係數、GWP 版本與計算結果**，之後係數更新不會改動已核准的歷史數字，查證時可完整重現。

## 8. 風險與盲點清單

**盤查方法**
1. 組織邊界與基準年須先定，後續比較皆依賴。
2. 範疇二：GHG Protocol 建議雙報；目前無綠電，僅位置基準，保留市場基準欄位。
3. 排除與重大性門檻須記錄理由，查證時會被問。
4. 每筆資料標示數據品質（實測／帳單／估算）；無歷史資料故估算占比可能偏高。
5. 範疇三 15 類先篩選再收集，避免負擔過重。

**生技業特有排放源（容易漏）**
6. 冷媒：超低溫冰箱、冰水主機、空調逸散，GWP 高。
7. 乾冰與液態二氧化碳（冷鏈、培養箱、實驗）。
8. 動物房麻醉氣體。
9. 冷鏈物流與檢體運送。
10. 實驗廢棄物與拋棄式耗材。
11. 公務車、員工通勤、出差。

**系統與營運**
12. 佐證與稽核軌跡：誰在何時改了什麼都要留痕。
13. 期間鎖定與解鎖申請流程。
14. PDF 中文字型須內嵌。
15. 內網離線：函式庫與字型本地放置。
16. 截止日前 Email 提醒未填報者。
17. 資安：PDO／Eloquent 參數化、密碼雜湊、CSRF、上傳驗證、HTTPS、備份。
18. 指定係數維護者，每年更新並覆核環境部與能源署公告。
19. 預載係數非保證最新，上線前須由公司逐筆核對（提供核對清單頁）。
20. 支出係數在台灣公開資料有限，須在方法學與報告中說明粗估性質。
21. 法規定位：《氣候變遷因應法》主要管制排放大戶，喜躍生醫多屬自願盤查；請依現行法規再核對。
22. 建議各部門在開發期間先整理 2025 年帳單與紀錄，上線即可回補。

**SQLite 注意事項**
23. 開啟 WAL；每日備份資料庫檔與上傳目錄；50 人規模寫入量足夠。
